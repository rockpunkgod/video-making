# Video production handoff

For video production or module changes, start with
[the current production entry](docs/workflows/CURRENT_PRODUCTION_WORKFLOW.md).
It is the single maintained source of current creative requirements and their
scope. Use its current revision and existing adaptive-episode entry; inspect
actual receipts before repeating production. Preserve unrelated dirty work.
For every new or revised narration, run the current entry's `script` operation
and send the entire exact copy in chat for the user's independent review.
An exported file or silence from the user is not copy approval. Continue
independent implementation while keeping copy, visual and film reviews separate.

For each change, identify the affected requirements, compatible inherited
requirements, actual consumer, visible/audible effect, and relevant regression.
Do not silently replace compatible decisions with an experiment's defaults.
Module tests, native execution, a local proof, human creative/listening review,
student results and publication are separate claims. Private sources and media
stay in ignored local data. Shared Adobe ownership and identity readback apply
across worktrees; uncertainty requires inspection, never blind replay.

Do not reintroduce the known reading defects. Current production uses the shared
native reading rig through `authored_native.template_source`, and `audit` checks
all authored reading windows (including scope, hit and revisits), complete native
rows, left-to-right phrase focus, source return, and a faded query margin before
its out-point. `render` runs that audit. Read the actual encoded handoff frames
and watch the result; data checks never constitute aesthetic approval. Preserve
compatible accepted camera, 3D, extraction, voice and method-expression decisions.

Before a new prepare/build, act as the article language editor: read each full
frozen passage and author `ARTICLE_CHUNKS.json`, then run the existing entry's
`chunks` operation. Follow the sense-group rules in the current workflow. Never
use equal word counts or AE line breaks to decide English phrase boundaries.
Keep source-exact fixed expressions, noun phrases and names together, including
fragile phrases in `keep_together`. This is language editing, not new ANSWER
analysis. The compiler checks coverage/bindings; it does not understand English
or grant human approval. AE consumes the compiled identities with native
noBreak; an oversized group requires a layout/language decision, never an
automatic split. Repeated reading windows reuse the same article groups.

New FREE_SHOWCASE production must include `AV_AUTHOR.teaching_focus`, validated
against all frozen candidate checks and actual method executions. Use the
existing `script -> chunks -> voice -> align -> prepare -> build -> audit -> render` entry.
`prepare` consumes the allocation into real take/caption/decision timing and the
native template consumes light checks versus critical comparisons. Do not turn
backstage units, ratings or full reasoning fields into spoken micro-lessons.
Difficulty is an explicit editorial hypothesis until actual student evidence
exists. Never force two remaining options, remove a difficult option to improve
the time-share metric, or trade readable evidence for a higher density number.
Preserve historical inputs for inspection; they cannot authorize a new build
without the current allocation. Tests and compiled time shares are not viewing
approval, student results or publication permission.
