# FREE_SHOWCASE：先写完整故事，再做真实叙事预演

本次限定制作基线为 `3f30b668496ce8fe6d08906daab0305cecd0d889`。这是一次作品修订，不新增 Narrative Runtime、人格评分器或视频模板。真实题目、完整台词、逐字声音、媒体和审阅材料均在忽略的本地 `local-data/narrative-r1/` revision，不能凭本页重建或推定其内容。

## 创作与既有接口的关系

1. 先核对实际 Episode、所供当前 Status、Action/Review 与实际媒体；查清哪段画面被认可。一次动作或入场的认可不传给后来的整片。
2. 对着实际旧句和时码诊断。把“题干、证据、动作、对照、结论”等后台义务保留在审核中，不把每个字段自动变成一段口播。
3. 从真实差异写完整、可连续朗读的故事，再拆进镜头、声音槽、字幕和来源引用。Student POV 的默认投影是绑定工具，不是整片的句式模板。
4. 两题要有不同观看理由；前一道只支持局部结果，就按该范围结束。不能为高潮补答案，也不能让后一条事实成为前一条判断的虚假依据。
5. 只有回看能增加新理解时才做局部回放。否则可采用“动作先行、比较处停留”的有据对照。回放不得复活候选或再执行一次已发生的排除。
6. 新稿必须产生新逐字 take、新字幕、新时间线和媒体绑定。维持 `voice-delivery/v1`，保留旧 take；声音完整放置，不后期加速或截短来塞旧镜头。

表达人格来自对当前题目的取舍与判断，不来自虚构履历、不断自称“我”或固定口头禅。画面已完成的动作不逐一复述；不能用持续的短指令代替连续思考。自然度与助手感仍需看实际作品。
