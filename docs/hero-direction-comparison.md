## 面向学生的成片规则

方法编号属于内部追溯信息，不进入最终口播、字幕或画面。消费者版本删除可见的
方法编号，将内部路由说明改写为学生能理解的下一步，例如“还需核对”。保留具体
检查项目、否定条件和停止边界；不得借清理标签删掉教学限制。

`creative_os.consumer_copy.project_consumer_contract` 消费原有已验证契约及新的
文案修订，显式修改/移除指定文字节点，再执行全部冻结绑定与文案完整性校验。
新文案需要新的内部 fidelity review，copy lock 与渲染契约重新计算，不能沿用旧
编辑批准。方法 ID、claim refs 和上游材料继续保存在后台记录，不改 ANSWER。

消费者契约重验证及 PR 最终编辑入口都会检查口播、屏幕文字、实际文字节点和
显示的原文片段，阻断 R/F/G 系列两位方法编号。该检查是确定性显示规则，不是
教学语义认证；学生用语是否自然仍需编辑判断。旧试片保留为历史，交付新修订。

消费者修订已完成三条本地原生成片，实际文字层/字幕、冻结绑定、相同音频和
无损 Hold 均检查通过；相关测试共 81 项通过。口播不变，屏幕编号清除，后台
claim/method/evidence/review 引用保留。公开发布状态仍独立记录。

最新用户要求允许质疑和改良原有设计语言。因此新一轮 G/H/I 比较信息组织方式，
不把固定双栏、抽离→路径→封口、Method Stamp 或 5px 微锁定当作普遍规则。
保留的是冻结事实、逐句归属、停止边界、中文可读性和真实阅读停顿。

| 新方向 | 组织方式 | 取舍 |
|---|---|---|
| G · 原文批注 | 原句固定，判断在空位下方出现，边界接替判断 | 原文容易回看；画面较安静 |
| H · 单焦点叙事 | 原句、名词节点、停止边界依次占据主要阅读区 | 主次鲜明；后段不能同时回看原句 |
| I · 证据对照 | 原文一直留在左侧，判断及边界在右侧接替 | 证据可追踪；同屏阅读量较大 |

新方向由 `creative_os.hero_narratives.make_narrative` 生成，接受已验证 Hero 和
当前冻结上游输入。它重新安排时间和位置，不修改文本或文本所属 unit。
输入文本角色不符时显式拒绝；不再宣称这些变体实现既有 Extract–Route–Seal
视觉签名。上一轮 D/E/F 保留为历史配色/排印比较，不冒充三种不同叙事。

执行 `python -m creative_os.hero_narratives <local-request.json>`，请求字段与下文
排印变体相同，但无需 `profiles`；三个叙事配置随模块版本保存。先验证全部变体，
再写入新的输出目录，保留旧修订。

三个新方向仍使用同一段 14.75 秒口播、声音计划和受保护屏幕文字；最终输出
必须经原生 AE 审计、PR 字幕与音轨核验、实际画面审阅。代理偏好不等于人工批准。

## 上一轮排印变体

本轮针对同一个冻结 Hero 增加 D/E/F 三个方向。之前 A/B/C 的规格和本地修订保留。
三个方向使用相同教学摘录、口播、夜曲、稀疏 SFX、14.75 秒时长与停止边界，
便于把观看差异归因到视觉。只实际制作 G01 Hero。

| 方向 | 构图与气质 | 重点检查 |
|---|---|---|
| D · 排印海报 | 近白底、无衬线、大结果字、下移路径 | 大字与 Stop/Method Stamp 的间距 |
| E · 结构蓝图 | 深蓝底、上移原文、较低结构轴、浅色字幕阅读区 | 深浅区域对比及封口识别 |
| F · 书页批注 | 暖纸底、衬线英文、上移结果、细线分隔边注 | 留白、阅读秩序及批注区的文字间距 |

共享的抽离动作保留同一个空位。源文字在抽离通道交叉前先降低层级并归位，
避免移动中的空位穿过仍在运动的单词。最后 5px 微锁定与停止后的 Hold 保留。
书页版功能标签避开边注分隔线。方向生成不会新增答案、证据或教学适用条件。

## 可重放流程

`python -m creative_os.hero_directions <local-request.json>` 只生成视觉契约。
请求包含已有冻结输入的 `package`、`manifest`、`statuses`、`full_delivery`、
`excerpt`，以及 `base_contract`、`profiles`、`revision`、`output`。
`profiles` 使用 `ae/design/legacy/swiss-cognitive-directions-v0.5.json`。
输出必须是新的目录；所有变体校验成功后才写入，禁止覆盖历史。

沿用 [Hero 工作流](cinematic-hero-workflow.md) 完成原生制作：

1. 在新 AEP 修订中建立三个原生合成，取得 Hook、过渡、Core、Stop 静帧。
2. 检查静帧并修订构图，再审计原生文字、关键帧与表达式，导出无音轨视觉段。
   本机 H.264 渲染曾使 AE 退出，本轮显式核对崩溃后的队列并停用失败任务，
   改用 `render_intermediate`：原生 TIFF 序列 → 软件编码无声视觉段。
   每帧编号连续、数量完整且保存 hash 后才交付 PR；这不是自动盲重试。
3. 同一 AEP 包含多个渲染时，全部渲染完成后才冻结项目 hash 与各自 handoff。
   保存项目会改变文件 hash，不能沿用首次渲染时的项目指纹。
4. 每个方向另存 PR 工程，替换冻结视觉段，保留经核验的音轨与字幕。
   导出前检查当前上游状态、声音覆盖与所有配乐关键帧。
5. 导出实际字幕 sidecar，核验字幕与口播对应；冻结实际显示帧的来源审阅绑定。
   原生轨道样式名称相同不代表每个 cue 的覆盖值相同；逐条检查双行和单行字幕
   的实际安全边距，不能只检查最后一句。
6. 全量解码，并比较三条试片音频样本；通过静止帧和过渡帧审阅后交付。

历史已冻结工程应先复制到新修订再保存。若历史 AEP 被重新保存，原文件 hash
绑定即失效，即使视觉契约相同；保留历史凭证与失效原因，不能静默改写旧收据。

代理推荐只是创意建议。三方向均为内部试片，不自动取得人工方向、教学、来源、
编辑或音乐许可。实际题面、录音、试片、Adobe 工程和运行记录均留在忽略目录。
